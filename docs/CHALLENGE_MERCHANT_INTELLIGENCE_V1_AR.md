# الجولة الثالثة — Merchant Intelligence Challenge v1

> **اكتب أقل قدر من الذكاء الاصطناعي الذي يجعل التاجر أسرع، لا أكبر قدر من الذكاء الاصطناعي الذي يجعل المشروع أثقل.**

## إعلان التحدي

أمامك تطبيق حقيقي اسمه **Clothing Ad Studio**. هو ليس صفحة فارغة ولا Demo: يملك محرر Canvas، وخمسة مقاسات، ومقاييس جودة، وسجل عمليات، وثيمات بصرية، وتخزيناً محلياً، ومساراً محلياً دائماً لإنشاء الإعلان. مهمتك ليست بناء Chatbot ولا إعادة كتابة Canvas. مهمتك أن تجعل صاحب المحل يكتب أمراً عربياً واحداً فيُترجم إلى تغيير **محدد، آمن، وقابل للتحقق** في الإعلان.

لن يفوز من يذكر كلمة AI أكثر. يفوز من يثبت أن التاجر يستطيع قول «كبّر صورة الملابس واستخدم النمط الليلي وأخفِ العنوان» وأن التطبيق يحوّل ذلك إلى أوامر typed، يطبّقها على الإعدادات الحالية فقط، ويتحقق من الناتج عبر سلسلة الجودة الموجودة، ويعمل حتى عند عدم وجود إنترنت.

## النسخة المرجعية والوصول

ابدأ بآخر SHA في فرع `main` وسجله حرفياً داخل التقرير. لا تبدأ من SHA مكتوب في رسالة قديمة ولا من ZIP قديم. استخدم [دليل الوصول الموحد](AI_CHALLENGE_ACCESS.md) ثم اقرأ بالترتيب: `AI_CONTEXT.md`، و`shared/types.ts`، و`shared/designDocument.ts`، و`shared/templateThemes.ts`، و`client/src/pages/Home.tsx`، والاختبارات المتصلة بالتخزين والجودة. رابط Render للقراءة البصرية فقط؛ ليس بيئة اختبار أو ضغط.

أي Patch لا يطبق نظيفاً على SHA الذي يسجله صاحبه يعامل كتسليم غير قابل للدمج.

## الهدف المحدد للجولة

تنفيذ **Merchant Command Pilot v1 — كتابة فقط**. لا تدخل الصوت في هذه الجولة؛ التعرف على الكلام مرحلة مستقلة لأنه يغيّر المتطلبات والأداء والخصوصية. يجب أن يدعم الـPilot حقولاً محلية منظمة، وأوامر عربية قصيرة، وتخزيناً محلياً انتقائياً للتفضيلات، ثم يمرر التغيير عبر محرك التصميم الموجود من دون تغييره جذرياً.

### مسار التنفيذ الإلزامي

```text
نص عربي من التاجر
        ↓
Rules-first parser محلي
        ↓
MerchantCommand أو MerchantCommand[]
        ↓
Schema validation + allowlist
        ↓
Reducer حتمي للإعدادات الحالية
        ↓
Design Replay / DesignDocument / DesignContract / Quality Gate
        ↓
Canvas الحالي والإعلان النهائي
```

لا يُسمح بتمرير نص المستخدم مباشرة إلى Canvas أو CSS أو React state أو `eval` أو أي منفذ تنفيذ عام.

## النطاق الوظيفي الإلزامي

### 1. ذاكرة التاجر المحلية

أنشئ طبقة محلية صغيرة باسم مثل `MerchantProfile` أو استعمل `StoreSettings` الحالي، بشرط **عدم تكرار البيانات الموجودة**. تحتفظ فقط باسم المتجر، والموقع، والهاتف أو واتساب، وفئة المتجر، والثيم المفضل، والألوان الافتراضية، وتفضيلات العرض المدعومة فعلاً. لا تحفظ محادثة كاملة ولا صوراً ولا مفاتيح ولا أسراراً.

الحفظ يكون محلياً على جهاز التاجر، مع زر واضح للمسح الكامل. لا يتم الحفظ التلقائي لمعلومة شخصية غير موجودة في نموذج متجر صريح أو موافقة واضحة من التاجر.

### 2. عقد الأوامر typed ومغلق

العقد يجب أن يكون discriminated union أو Zod schema مكافئاً، وأن يقبل **العمليات التالية فقط** في النسخة الأولى:

| الأمر الآمن | الحقول أو الحدود القائمة | مثال عربي مطلوب |
|---|---|---|
| `set-visual-theme` | `classic`, `midnight`, `rose`, `mint`, `sand` فقط | «استخدم القالب الليلي» |
| `adjust-product-scale` | زيادة أو نقصان محصوران بين `0.85` و`1.5` وبخطوة الإعداد الحالية | «كبّر صورة الملابس» |
| `set-element-visibility` | `showHeadline`, `showPrice`, `showProductName`, `showDiscount`, `showFeatures` فقط | «لا تظهر العنوان» |
| `set-store-field` | `storeName`, `storePhone`, `storeLocation`, `storeCategory` فقط | «اسم المحل الأناقة» |
| `set-default-colors` | ألوان نصية قصيرة ومنظفة، لا CSS خام | «ألواني المفضلة أسود وذهبي» |

لا يوجد في العقود الحالية خيار `priceSize` أو تحريك حر لاسم المتجر أو لون CSS عشوائي. إذا قال المستخدم «كبر السعر» أو «ضع اسم المحل فوق»، يجب أن يكون الناتج **`unsupported` مع رسالة عربية مفهومة**، لا اختراع إعداد أو تغيير خفي. يمكن للمتسابق إضافة أمر جديد فقط إذا وسّع العقد والـCanvas والـDesignContract والاختبارات معاً ويثبت السبب؛ لا يمنح ذلك نقاطاً مجانية.

### 3. Rules أولاً

يجب أن تنجح مجموعة الأوامر الإلزامية في وضع Offline بلا نموذج لغة وبلا طلب شبكة. استخدم قواعد عربية محدودة وdeterministic للأوامر الواضحة. الناتج المسموح به: أمر واحد، مجموعة أوامر مرتبة، أو `unsupported`/`needs-clarification`.

الأوامر الغامضة لا تُحوَّل إلى تخمين. مثال: «خله أجمل» يعيد توضيحاً ولا يغير التصميم. مثال: «كبّر السعر وخلي صورة الملابس أكبر» ينتج أمرين، ولا يغير أي حقل آخر.

### 4. طبقة نموذج محلي — اختيارية ومقيدة

إضافة نموذج لغة ليست مطلوبة للفوز. إن اختار المتسابق تضمينها، يجب أن تبقى اختيارية ومؤجلة خلف زر موافقة واضح، وأن تعيد **اقتراحاً structured** يمر بالعقد نفسه ولا تطبق تغييراتها مباشرة. لا تُحمَّل أوزان النموذج مع الحزمة ولا تُضمّن في Git ولا تُطلب عند فتح التطبيق.

`Qwen/Qwen3-0.6B` مرشح دراسة فقط، وليس اختياراً مفروضاً؛ صفحته الرسمية تعرض ترخيص Apache-2.0، لكن ذلك لا يثبت ملاءمته لهاتف المستخدم أو تشغيله عبر متصفح المشروع. [1] يجب مقارنة هذا الخيار بمسار «Rules فقط» وبمرشح واحد على الأكثر، مع قياسات حقيقية أو حالة `NOT VERIFIED`.

WebGPU ليس ضماناً: توثيق Transformers.js يصفه بأنه تجريبي في متصفحات كثيرة. [2] لذلك لا يقبل تسليم يجعل WebGPU شرطاً لإنشاء الإعلان. عند عدم دعمه، يستمر الـRules parser وكل محرر الإعلان، ولا يظهر نموذج WebAssembly كبير بوصفه fallback افتراضياً من دون قياس تنزيل وذاكرة حقيقيين.

## شروط الأمان والخصوصية

لا يملك الـparser أو النموذج المحلي أي صلاحية لتنفيذ JavaScript، تعديل ملفات المشروع، قراءة الأسرار، إرسال النصوص أو الصور إلى الإنترنت، تعديل `DesignContract` مباشرة، أو تغيير خصائص غير موجودة في allowlist.

كل تغيير يمر بالترتيب التالي، ولا يجوز اختصاره:

```text
ناتج قواعد أو نموذج
→ validate schema
→ allowlist commands
→ deterministic reducer
→ existing design validation
→ apply أو reject
```

يحظر أي API مدفوع أو مفتاح API أو خدمة خارجية إجبارية. لا تضع أوزان نموذج أو صور أو ملفات `node_modules` في المستودع. عند استعمال مصدر خارجي اختياري للأوزان، وثّق الرابط والترخيص والبصمة إن توفرت، ولا تنزّل شيئاً خلال الاختبارات الافتراضية.

## ميزانية الأداء والقياس

المسار الإلزامي Rules-first لا يضيف اعتماداً ثقيلاً ولا طلب شبكة. أي طبقة نموذج اختيارية تُحمّل lazy بعد موافقة صريحة، ولا يسمح لها بكسر سقف الحزمة الأولية الحالي أو التسبب في إعادة تنزيل متكرر. لا تقبل أرقاماً منمقة أو قياسات من جهاز مختلف من دون وصف البيئة.

| قياس مطلوب | Rules-first | نموذج اختياري |
|---|---|---|
| حجم كود التغيير والحزمة بعد البناء | مطلوب | مطلوب |
| زمن تفسير 20 أمراً ثابتاً | مطلوب | مطلوب إن أضيف |
| أول تشغيل للنموذج بعد الموافقة | غير منطبق | مطلوب أو `NOT VERIFIED` |
| حجم تنزيل الأوزان والدقة والترخيص | غير منطبق | مطلوب |
| WebGPU وfallback وسلوك جهاز بلا WebGPU | parser يعمل | مطلوب |
| Offline بعد إغلاق الشبكة | مطلوب | مطلوب بعد تنزيل مقصود إن ادّعى دعمه |
| RAM/الاستقرار على الهاتف | وصف وتحقق متصفح | قياس أو `NOT VERIFIED` |

## الاختبارات الإلزامية

لا يكفي اختبار دالة نصية معزولة. أضف اختبارات وحدة وعقد وواجهة/تدفق حيث يلزم، ثم شغّل الأوامر الفعلية للمشروع. الحد الأدنى:

1. «محل الأناقة في صنعاء» يحدّث حقول المتجر المحددة فقط، ويحفظ محلياً.
2. «استخدم القالب الليلي» يختار `midnight` فقط.
3. «كبّر صورة الملابس» يرفع `productScale` ضمن الحد ويعيد الرسم عبر المسار الحالي.
4. «كبّر صورة الملابس وأخفِ العنوان» يطبق الأمرين بالترتيب، ولا يغير السعر أو الشعار أو المقاس.
5. «غير اللون فقط» لا يحق له اختراع لون Canvas عشوائي؛ إما يحدّث `defaultColors` أو يعيد أمراً غير مدعوم موثقاً.
6. أمر غير معروف لا يغير أي حالة.
7. نص يشبه كوداً أو تعليمات حقن لا يصبح كوداً ولا يخرج من allowlist.
8. مسح Merchant Memory لا يمسح إعدادات القالب غير المتعلقة بالذاكرة أو صور الإعلان.
9. وضع Offline يبقي إنشاء الإعلان المحلي والـRules parser صالحين من دون شبكة.
10. إعادة فتح التطبيق تستعيد التفضيلات المقصودة فقط.
11. إعادة فحص DesignContract وQuality Gate بعد تطبيق أمر مغير للتصميم.
12. اختبار انحدار لكل الاختبارات القائمة.

شغّل فعلياً وسجّل المخرجات:

```bash
pnpm test
pnpm check
pnpm build
pnpm perf:check
pnpm mobile:check
```

أي أمر لم يجر تشغيله يكتب `NOT VERIFIED` مع السبب، وليس PASS.

## ممنوعات تؤدي إلى الرفض

يرفض التسليم فوراً إذا بنى Chatbot شكلياً، أو جعل النموذج يغير React/Canvas مباشرة، أو استعمل API مدفوعاً أو مفتاحاً في الواجهة، أو ضمّن نموذجاً ضخماً أو أوزانه داخل Git، أو أعاد بناء Canvas/DesignContract من الصفر، أو خزّن محادثات كاملة، أو ادعى قياسات أو اختبارات لم يشغّلها.

يرفض أيضاً إن غيّر خصائص تصميم غير موجودة في المشروع، أو عالج «كبر السعر» كأنه موجود بينما لا يوجد عقد أو رسم واختبار يثبت ذلك.

| المحور | النقاط | ما يثبت الفوز |
|---|---:|---|
| أوامر typed صحيحة وتكامل فعلي | 30 | أوامر عربية تغير إعدادات موجودة فقط وتصل إلى الإعلان الحالي |
| Local-first وتجربة التاجر | 20 | Rules تعمل بلا شبكة، ذاكرة محدودة ومسح واضح، وواجهة صغيرة مفهومة |

## التسليم الإلزامي

يسلّم المتسابق **ملف ZIP واحداً نظيفاً** يحتوي فقط على:

```text
PATCH.diff
changed-files/
CHALLENGE_REPORT.md
ARCHITECTURE.md
MODEL_SELECTION.md
TEST_RESULTS.md
PERFORMANCE.md
SECURITY_REVIEW.md
```

يذكر التقرير SHA الأساس، الملفات المعدلة، ما أضيف فعلياً، الأوامر التي شغّلت ونتائجها، وما لم يمكن التحقق منه. لا ترسل مشروعاً كاملاً ولا `node_modules` ولا أسراراً ولا ملف `.env` ولا أوزان نموذج ولا بيانات مستخدمين.

## السؤال الحاسم للمتسابق

> أثبت كيف تجعل التاجر يكتب جملة عربية واحدة، فيفهم التطبيق **فقط ما تسمح به عقوده الحالية**، ويتذكر تفضيلاته المقصودة محلياً، ويعدل الإعلان فعلياً، ويظل التطبيق سريعاً وآمناً ويعمل بلا إنترنت — من دون أن تتخفى خلف Chatbot أو API أو نموذج ثقيل.
