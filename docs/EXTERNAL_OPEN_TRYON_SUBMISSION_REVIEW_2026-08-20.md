# مراجعة تسليم الوكيل الخارجي لمسار Virtual Try‑On

**التاريخ:** 20 أغسطس 2026  
**المدخلات المراجعة:** `الحل_والخطة.md` و`vtonManager.js` و`أمثلة_طلب_واستجابة.md`  
**الحكم:** **مرفوض للدمج حالياً — يمكن الاحتفاظ بفكرة «مدير Try‑On متعدد المراحل» فقط.**

## الخلاصة

الفكرة العامة جيدة: تبدأ بصورة القطعة المعزولة محلياً، ثم تستدعي محرك Try‑On متخصصاً، وتعرض النتيجة للمراجعة قبل اعتمادها. كما أن تفضيل نموذج متخصص على مولد صور عام منطقي لأن المهمة تستهدف الحفاظ البصري على القطعة.

لكن التسليم لا يصلح للدمج: ادعاؤه الأساسي حول «100 طلب ModelsLab مجاني يومياً» غير صحيح وفق صفحة التسعير الرسمية الحالية، والكود لا يطابق عقد ModelsLab الرسمي، كما أنه يعامل Space عام في Hugging Face كأنه API احتياطي دائم بلا حدود. كذلك يقترح مسارات غير موجودة في المشروع (`Gemini Gems` و`CapCut`) ويتجاوز طبقة Try‑On الخادمية والواجهات الموجودة فعلاً.

> **القرار:** لا نضيف `vtonManager.js` ولا Cloudflare Worker ولا مزوداً جديداً. يبقى مسار Try‑On الاختياري الموجود، مع الرجوع المحلي، بلا تغيير.

## التحقق من المزودين

| المقترح | التحقق المستقل | القرار |
|---|---|---|
| **ModelsLab Fashion API** | الخدمة تقدم Try‑On فعلاً، لكن صفحتها الرسمية تصفه مدفوعاً من `$0.0047` للصورة وخطط من `$21/month`. وتقول صفحة التسعير صراحة إنه **لا توجد خطة مجانية أو أرصدة مجانية أو تجربة**. [1] [2] | **مرفوض:** لا يحقق شرط المجانية بلا بطاقة. |
| **ModelsLab كودياً** | التوثيق يطلب `init_image` لصورة الشخص و`cloth_image` لصورة القطعة و`cloth_type`، مع مفتاح API وطلب JSON إلى مسار v6. الكود المرفق يرسل `garment_image` و`garment_type` و`gender` فقط بصيغة multipart إلى proxy افتراضي؛ لذلك لا يطابق العقد ولا يملك صورة الشخص المطلوبة. [3] | **مرفوض:** لن يعمل كما هو. |
| **Kolors Space** | الـSpace العام هو Demo يعمل حالياً على CPU، وليس عقد API مخصصاً للتطبيق. وثائق Hugging Face تصف Spaces كبيئات ينشرها مالكها، ويمكن أن تنام وتتوقف عند عدم الاستخدام على العتاد المجاني؛ ويمكن للمالك تغييرها أو حذفها. [4] [5] | **مرفوض كاحتياطي تلقائي:** مناسب لتجربة يدوية فقط، وليس «مجانياً بلا حدود» أو endpoint مضموناً. |
| **FASHN API** | FASHN يقدم `product-to-model` وهو بالفعل مناسب أكثر لمسار صورة قطعة → شخص افتراضي. لكن صفحة API تطلب شراء أرصدة تبدأ من `$7.50`. أما العشرة أرصدة المجانية الظاهرة في صفحة الأسعار فتخص حساب التطبيق التجريبي ولا تثبت رصيد API شهرياً متجدداً. [6] [7] | **لا يدمج الآن:** يحتفظ به كخيار مستقبلي فقط عند قرار صريح بإعداد مفتاح ورصيد. |

## ما يحتفظ به من الفكرة

يمكن الاحتفاظ بمبدأ **المدير الذكي** لاحقاً، لكن بوصفه طبقة قرار صغيرة داخل الخادم الموجود: يختار مزوداً مهيأً فعلاً، يمرر فقط قيم الإدخال المعتمدة، ويحفظ موافقة المستخدم، ويعيد دائماً إلى الصورة المحلية عند الفشل. لا نحتاج إلى Cloudflare Worker لأن المشروع يملك خادماً Express وطبقة Try‑On خادمية بالفعل؛ إذا وُجد مفتاح مرخص مستقبلاً يوضع في متغير خادم فقط.

## المطلوب من النموذج إن أعاد التسليم

يحتاج النموذج إلى إعادة التسليم مع مزود واحد فقط تتطابق مجانيته الحالية مع وثائقه الرسمية، وعقد طلب دقيق، وPatch TypeScript صغير يوسّع `server/tryOn.ts` بدلاً من إنشاء JavaScript مستقل. إن لم يوجد مزود مجاني مؤهل، فالتسليم الصحيح هو توثيق صادق لمسار يدوي/تجريبي لا يُدمج في التطبيق، وليس اختراع حصة أو endpoint أو ملفات أساس غير موجودة.
