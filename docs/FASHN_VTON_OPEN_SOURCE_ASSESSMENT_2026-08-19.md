# تقييم FASHN VTON v1.5 المفتوح المصدر

**التاريخ:** 19 أغسطس 2026  
**الحكم:** النموذج مفتوح المصدر فعلاً، لكنه **ليس بديلاً مجانياً جاهزاً** لتكامل Product-to-Model الحالي ولا يصلح للتشغيل داخل الاستضافة الحالية أو الهاتف.

## ما تأكد رسمياً

| الادعاء | النتيجة المتحققة | الأثر على المشروع |
|---|---|---|
| نموذج FASHN VTON v1.5 مفتوح | صحيح؛ الكود والأوزان منشورة برخصة Apache-2.0. | يمكن دراسته أو استضافته ذاتياً مع احترام رخص المكونات التابعة. |
| تطبيق Next.js رسمي | صحيح، لكنه عميل لـFASHN Virtual Try-On API ويطلب `FASHN_API_KEY`. | لا يزيل تكلفة أو مفتاح خدمة الـAPI، ولا يقدّم تشغيل النموذج المفتوح محلياً. |
| الاستدلال مجاني على أي جهاز | غير صحيح. الأوزان الأساسية تقارب 2 GiB، ويُنزّل محلل بشري إضافي بحجم 244 MiB، وتوصي الوثائق بـGPU مخصص. | لا يعمل عملياً على هاتف المالك أو WebDev Autoscale الحالي. |
| النموذج يعوض Product-to-Model الحالي | غير صحيح. النموذج المفتوح يتطلب **صورة شخص حقيقية** وصورة قطعة وفئة (`tops` أو `bottoms` أو `one-pieces`). | لا يولّد النموذج الافتراضي تلقائياً؛ يلزم مصدر صورة نموذج مرخّص يختاره المستخدم أو مزود Product-to-Model منفصل. |

## متطلبات التشغيل الواقعية

> بطاقة النموذج الرسمية تذكر نحو 8 GiB من VRAM للاستدلال، ودقة خرج 576×864، وتوصي بـGPU مخصص لسرعة معقولة. كما تشير إلى نحو 5 ثوانٍ على H100؛ لا يجوز إسقاط هذا الرقم على GPU مجاني أو CPU. [2]

النموذج يحوي نحو 972 مليون معامل ويستخدم PyTorch، بينما يتضمن دليل المشروع `onnxruntime-gpu` لاكتشاف الوضعية ويتطلب إعداد CUDA للتشغيل المسرّع. يدعم CPU شكلياً، لكن الوثائق لا تقدم زمناً عملياً له. [1] بيئة المشروع الحالية لا تحتوي GPU (`nvidia-smi` غير موجود) ولديها نحو 4 GiB من RAM؛ لذلك لم نحمّل الأوزان أو نجرب استدلالاً ناقصاً أو مضللاً.

المساحة الرسمية على Hugging Face ظاهرة بوصفها **Running on ZERO**، وتبقى مناسبة لاستكشاف يدوي عام فقط. لا تعد خدمة مضمونة أو مستقرة أو مكاناً ملائماً لإرسال صور التاجر تلقائياً من التطبيق، ولا تظهر بطاقة النموذج مزود Inference Provider منشوراً لها. [2] [5]

## التوافق مع تطبيق الملابس

التكامل الموجود في `server/tryOn.ts` يخدم Product-to-Model عبر FASHN API: يرسل صورة قطعة وإعداداً ثابتاً للعرض، ثم يعيد نتيجة للاعتماد قبل Canvas. أما FASHN VTON المفتوح فيحتاج صورة شخص. لذلك لا يمكن تبديل `FASHN_API_BASE_URL` بنموذج مفتوح ببساطة؛ يلزم Adapter جديد، خدمة GPU منفصلة، وتحديد مصدر شخص مرخّص مع سياسة احتفاظ وحذف للصور.

التنفيذ الحالي في التطبيق يبقي Try-On اختيارياً، يتطلب موافقة قبل الشبكة، ولا يدمج النتيجة قبل اعتماد المستخدم، ولا يسمح لغياب المزود أن يوقف تجهيز الإعلان المحلي. هذه القواعد يجب أن تبقى كما هي مع أي تجربة نموذج مفتوح.

## القرار

لا نضيف النموذج المفتوح إلى مسار المستخدم الآن ولا ننشئ خدمة Docker أو GPU أو اعتماداً على مساحة مجانية. يبقى FASHN API الحالي هو Adapter المناسب عندما يضع المالك مفتاحاً خادمياً مرخصاً؛ وتبقى إزالة الخلفية المحلية هي المسار الافتراضي غير المتصل.

تكون تجربة FASHN VTON المفتوح التالية **تجربة هندسية منفصلة وليست ميزة إنتاجية** فقط عند توافر GPU موثق لا يطلب من المالك دفعاً أو الاعتماد على هاتفه. يجب أن تستخدم صور نموذج اختبار مرخّصة وغير شخصية، وتثبت زمن الاستدلال، الذاكرة، الحذف، ونتيجة الرجوع قبل ربطها بالتطبيق.
