# حالة النشر الإنتاجي وخطواته المؤجلة

## ما تم التحقق منه

المستودع العام على GitHub هو مصدر النشر الفعلي. أدى دفع الالتزام `3483554` إلى تشغيل **Quality Gate** على فرع `main`، واجتازت الخطوات تثبيت الاعتماديات والاختبارات والبناء وميزانية الأداء وفحص الهاتف بعرض 390px. بعد نجاح البوابة، وصل الإصدار الجديد إلى Render وتحقق فتح تبويبة «المساعد» من الرابط الحي.

| الخاصية | الحالة | الدليل |
|---|---|---|
| مزامنة GitHub من `main` | مفعّلة | وصل الالتزام `3483554` إلى المستودع ثم شغّل Quality Gate. |
| منع نشر نسخة تفشل الجودة | مفعّل | فشل تشغيل سابق عند فحص الهاتف، ثم لم يصل الإصدار حتى إصلاح البوابة ونجاحها. |
| النشر التلقائي إلى Render بعد جودة ناجحة | متحقق | وصل Merchant Assistant Foundation إلى الرابط الحي بعد نجاح البوابة. |
| استيقاظ خدمة Render المجانية | متوقع | الرابط قد يعرض صفحة تحميل مؤقتة قبل تشغيل النسخة بعد فترة خمول. |

## احتياطات الاستعادة والنشر

يمكن استعادة أي نسخة من خلال نقاط الاستعادة المحفوظة في المشروع أو تاريخ GitHub، ولا يجب الدفع إلى `main` قبل اجتياز الجودة محلياً. إذا توقف Render أو تأخر، يكون GitHub هو مصدر الحقيقة وتبقى آخر نقطة استعادة صالحة قابلة لإعادة النشر على خدمة متوافقة؛ لا تُنشأ خدمة بديلة أو حساب جديد من دون قرار المستخدم حتى لا تتشعب الأسرار وإعدادات قاعدة البيانات.

> لا ينبغي تفسير «الخدمة نائمة» في الخطة المجانية كفشل في الكود أو النشر. الفشل يستلزم سجل بناء أو تشغيل يثبت الخطأ.

## ما لا يمكن إكماله تلقائياً

| البند | سبب التوقف المقصود | ما يلزم قبل التنفيذ |
|---|---|---|
| متغيرات البيئة السرية لـRender | أي تغيير يحتاج جلسة مالك Render؛ لا تُرسل الأسرار في المحادثة أو Git. | دخول المستخدم إلى Render أو تفويض جلسة صالحة، ثم تدوير السر الذي ظهر سابقاً. |
| قاعدة بيانات مستقلة في Render | قرار المشروع السابق يمنع إنشاء قاعدة جديدة قبل خطة هجرة وأمان واختبار تراجع. | اختيار موثق بين MySQL على Render أو TiDB أو PostgreSQL بعد تقرير الاكتشاف، ثم بيانات اتصال سرية فقط عبر Environment Variables. |
| رموز الدخول على الرابط الحي | تعتمد على قاعدة البيانات الإنتاجية؛ لا يجوز تحويلها إلى تخزين متصفح أو تخزين داخل Git. | قاعدة بيانات مختارة وهجرة قابلة للتراجع وتحقق تشغيل حي. |
| بديل استضافة مستقل | يتطلب حساب مالك ونطاقاً وسياسة أسرار وتشغيل خاصة به. | قرار المستخدم حول مقدم الاستضافة وأسلوب إدارة الأسرار قبل إنشاء أي خدمة. |

## الخطوة التالية الآمنة

تظل الأولوية العملية هي جمع ملاحظات الأصدقاء حول استخدام التطبيق على الهاتف، ثم استكمال طبقة الحماية الإنتاجية وقاعدة البيانات وفق خطة الهجرة السابقة. لا يُدمج حل يلتف على قاعدة البيانات أو يخزّن أسراراً في الواجهة لمجرد تسريع هذه المرحلة.
