# قرار تنفيذ Virtual Try‑On v1

**الحالة:** جاهز للتنفيذ المقيد بعد مراجعة التغييرات المقترحة واختبارها. لا يغيّر هذا القرار أولوية المسار المحلي؛ إزالة الخلفية المحلية وCanvas هما المسار الافتراضي دائماً.

## 1. النطاق المعتمد

يصبح **Virtual Try‑On / Product-to-Model** خياراً واضحاً بعد رفع صورة القطعة ومراجعتها، وليس شرطاً لإنشاء الإعلان. يختار المستخدم فئة نموذج افتراضي ونوع القطعة ووضعية من قوائم ثابتة. لا يستنتج التطبيق عمر شخص أو جنسه أو هويته من صورة، ولا يرسل صورة وجه أو نموذج حقيقي في الإصدار الأول.

> لا تضاف نتيجة الشبكة إلى Canvas إلا بعد أن يراها المستخدم ويضغط «استخدم هذه النتيجة في القالب». عند الرفض أو غياب مزود أو الفشل، تبقى صورة القطعة ومسار الإعلان المحلي صالحين.

## 2. ما هو موجود ومتحقق في المشروع

| العنصر | الحالة | الملاحظة |
|---|---|---|
| tRPC محمي `tryOn.run` | موجود | يقبل صورة `data:image/*` حتى 12,000,000 حرفاً ونسبة `4:5` أو `9:16`. |
| FASHN Product-to-Model | موجود | يرسل `product_image` و`aspect_ratio` و`resolution: 1k` من الخادم فقط. |
| Perfect Corp Background Remove | موجود | يطلب URL رفع موقعاً، يرفع الملف، يبدأ المهمة ويستطلعها. |
| حفظ النتيجة | موجود | ينزّل الخادم نتيجة المزود ويتحقق من نوع الصورة وحد 15 MiB ثم يحفظها في التخزين. |
| Canvas لشخص بخلفية شفافة | موجود | يقبل `visualMode: transparentPerson` ويثبت الشخص على أرضية منطقة البطل. |
| واجهة موافقة واختيار ومراجعة | منفذة | تظهر بعد مراجعة صورة القطعة وقبل بيانات الإعلان. |
| منع التكرار وإلغاء صادق | منفذ في الواجهة | رقم طلب محلي يتجاهل النتيجة المتأخرة؛ لا يدّعي إيقاف مهمة مزود بدأت فعلاً. |

## 3. التحقق من وثائق المزودين

توثق FASHN أن `product-to-model` يستخدم `POST /v1/run` ويقبل `product_image` و`prompt` و`aspect_ratio` و`resolution` و`generation_mode` و`num_images` داخل `inputs`.[1] البنية الحالية متوافقة مع نموذج الطلب العام، لكنها لا تمرر اختيار النموذج للمستخدم بصورة مقيدة ولا توثق خصوصية التسليم.

توثق FASHN أن المخرجات القياسية عبر CDN مجدولة للانتهاء بعد ثلاثة أيام، بينما `return_base64: true` يقيد وصول المخرجات إلى 60 دقيقة ويخفي سلسلة Base64 الكاملة في سجل الطلبات، مع بقاء معلمات ومراجع الطلب في السجل.[2] لذلك يعتمد الإصدار الأول على إخطار صريح بأن صورة القطعة سترسل إلى FASHN وتستخدم نتيجة تُنزّل إلى تخزين المشروع؛ ولا يدّعي حذفا فورياً لدى المزود. لا يستعمل `face_reference` في هذا الإصدار.

توثق Perfect Corp أن إزالة الخلفية تتطلب طلب ملف ثم رفعاً فعلياً إلى URL الموقع ثم بدء مهمة `task/sod` واستطلاعها ضمن فترة الاستطلاع، وأن الصور JPG/PNG يجب أن تكون أصغر من 10 MB وألا يتجاوز أطول ضلع 4096 بكسل.[3] طبقة `server/perfectCorp.ts` الحالية تطابق تسلسل الرفع والاستطلاع، وتفشل بأمان إلى صورة الشخص غير الشفافة عندما تفشل إزالة الخلفية الثانوية.

## 4. رحلة المستخدم المقترحة

| المرحلة | واجهة المستخدم | قاعدة الأمان |
|---|---|---|
| رفع القطعة | مراجعة الصورة المحلية كما هي | لا توجد شبكة. |
| خطوة اختيارية | زر «جرّب على نموذج افتراضي» | لا يبدأ شيء تلقائياً. |
| اختيار محدود | فئة مظهر عامة، نوع قطعة، وضعية، ونسبة إخراج | تتحول إلى `prompt` ثابت من خريطة محلية؛ لا يوجد حقل حر يمرر بلا حد. |
| موافقة | اسم FASHN، صورة القطعة، سبب الإرسال، الحد التقريبي، زر قبول أو إلغاء | لا تطلب tRPC قبل الضغط على قبول. |
| حالة المعالجة | «قيد تجهيز نتيجة اختيارية» مع إلغاء واجهة | الإلغاء يمنع اعتماد النتيجة المتأخرة؛ لا يزعم إيقاف مهمة مزود بدأت فعلاً. |
| مراجعة | صورة نتيجة + «استخدم في القالب» و«ابقَ على الصورة الأصلية» | لا تتبدل `lastVisualSource` قبل الاعتماد. |
| الرسم | عند الاعتماد، استخدم `transparentPerson` فقط إذا كانت النتيجة شفافة | إن لم تكن شفافة، تعرض المعاينة كمراجعة فقط أو على خلفية مناسبة يوافق عليها المستخدم؛ لا تدّعي PNG شفافاً. |

## 5. عقد واجهة وخادم مقترح

توسع `tryOn.run` إلى مدخل Typed محدود:

```ts
{
  productImageData: string,
  aspectRatio: '4:5' | '9:16',
  presentation: 'women-fashion' | 'men-fashion' | 'kids-fashion' | 'accessories',
  pose: 'studio-standing' | 'lifestyle-standing',
  consent: true,
  consentVersion: 'tryon-v1'
}
```

يقوم الخادم بتحويل `presentation` و`pose` إلى Prompt ثابت. لا يستقبل `face_reference` أو رابطاً خارجياً أو مفتاحاً من العميل. يجب أن يتحقق من أن `consent` صحيح قبل بدء طلب FASHN. يمرر `prompt` و`generation_mode: 'fast'` و`num_images: 1` و`output_format: 'png'` صراحة كي تكون التكلفة والوقت والسلوك قابلين للفهم.[1]

## 6. الفشل والإلغاء ومنع التكرار

| الحالة | سلوك v1 الصادق |
|---|---|
| لا مزود أو مفتاح مفعّل | لا يظهر زر البدء أو يظهر سبب واضح؛ الإعلان المحلي مستمر. |
| رفض الموافقة | لا طلب شبكة ولا تغيير للصورة. |
| مزود يرفض الصورة أو تنتهي المهلة | حالة `fallback` مع الاحتفاظ بصورة القطعة؛ لا يعاد الإرسال تلقائياً. |
| ضغط مزدوج | قفل زر البدء لكل `requestId` محلي وإهمال نتيجة قديمة. |
| إلغاء بعد الإرسال | تجاهل النتيجة في الواجهة وعدم حفظها في مسار الإعلان؛ الإفصاح أن مهمة المزود قد تكون بدأت ولا يضمن التطبيق إيقافها. |
| فشل تفريغ الخلفية | تبقى نتيجة الشخص مراجعة فقط مع رسالة حقيقية؛ لا يرسمها كـشفافة. |
| نتيجة غير صالحة أو كبيرة | يرفض الخادم التنزيل/التخزين، ويعود للمسار المحلي. |

## 7. اختبارات القبول المطلوبة

1. لا يظهر أو لا يفعّل Try‑On عند غياب مزود مفعّل، ويبقى زر إنشاء الإعلان المحلي يعمل.
2. لا تستدعى `tryOn.run` قبل قبول الحوار الصريح.
3. تترجم كل اختيارات الواجهة إلى قيم مسموح بها فقط ولا تصل سلسلة Prompt حرة إلى الخادم.
4. طلب ناجح لا يغيّر Canvas قبل ضغط اعتماد النتيجة.
5. رفض النتيجة يعيد/يبقي صورة القطعة ولا يغير السجل المحلي أو Canvas.
6. فشل الشبكة والمهلة ورفض المزود ينتجون `fallback` ولا يمنعون الإعلان المحلي.
7. الضغط المكرر لا ينشئ أكثر من طلب واحد، والنتيجة المتأخرة بعد الإلغاء لا تطبق.
8. لا يظهر مفتاح API أو بيانات Base64 أو URL خارجي في `localStorage` أو سجل التصميم أو رسائل الواجهة.
9. تمر اختبارات Try‑On والخطوات المحلية القديمة وانحدارات الهاتف 390px وبوابة الجودة كاملة.

## 8. القرار

**نُفذ الإصدار الأول المقيد** من واجهة الاختيار والموافقة والمراجعة. لا يعتمد أي مزود في الإنتاج حتى يضيف المطور مفتاحه في لوحة المزودين الخادمية. تبقى مفاتيح المزودين غير موجودة في الكود والاختبارات، ويبقى عدم وجود مزود حالة عادية غير معطلة للمسار المحلي.

## 9. التنفيذ والتحقق المنجزان

أضيف المكون `TryOnOptIn` إلى خطوة مراجعة الصورة. لا يظهر في وضع اختبار الأصدقاء، ولا يبدأ اتصالاً خارجياً عند فتحه أو تغيير القوائم. يتطلب مربع موافقة صريحاً قبل تفعيل زر الطلب. تحوّل الواجهة الفئة والوضعية إلى قيم مقيدة، ويتحقق tRPC من `consent: true` ونسخة الموافقة ثم يحول الخادم القيم إلى Prompt ثابت. لا يمر وصف حر من المستخدم إلى FASHN.

لا تصبح النتيجة مصدر Canvas إلا إذا كانت استجابة ناجحة وPNG شفافة لشخص، ثم يضغط المستخدم «استخدم داخل القالب». تظل النتيجة غير الشفافة معاينة فقط، ويعيد الرفض أو الإلغاء المستخدم إلى صورة القطعة. في حالات عدم توفر المزود أو الفشل، تسجل الواجهة حالة رجوع ولا تمنع إزالة الخلفية المحلية أو إنشاء الإعلان.

أضيف اختبار لموافقة الواجهة واختبار لعدم اعتماد نتيجة غير شفافة، واختبار Prompt الخادمي المقيد. نجحت اختبارات Try‑On والواجهة المرتبطة **28 اختباراً**، ونجحت بوابة الجودة الكاملة محلياً بـ**215 اختباراً في 53 ملفاً**، مع TypeScript والبناء وفحص الأداء. بقي CSS عند 130 KiB ضمن السقف، واجتاز فحص الهاتف 390px بلا تجاوز عرض.
