# بحث بدائل Virtual Try‑On المجانية بلا بطاقة

**التاريخ:** 19 أغسطس 2026  
**النطاق:** مصادر المالك المقدمة، ثم Hugging Face Spaces وfal.ai وReplicate كمصادر إضافية موثقة.  
**الحالة:** **مكتمل — لا يوجد مزود مؤهل للدمج التلقائي ضمن القيود الحالية.**

## القرار التنفيذي

لم يظهر في المصادر المفحوصة مزود يجمع، في وقت البحث، بين **Virtual Try‑On حقيقي** و**واجهة خادمية موثقة** و**استخدام متكرر بلا بطاقة أو دفع** و**شروط صور وخصوصية مناسبة** و**استقرار كافٍ لرحلة المستخدم داخل التطبيق**. لذلك لن يُضاف أي adapter جديد أو مفتاح أو اتصال خارجي إلى المشروع في هذه الجولة.

> **القرار المعتمد:** يبقى مسار إعداد الإعلان المحلي هو المسار الدائم والموثوق. وتبقى واجهة Try‑On الاختيارية القائمة محكومة بموافقة صريحة وبفشل آمن؛ لن تعمل إلا عند إضافة مزود مرخّص لاحقاً بإرادة المالك، ولا تؤثر غيابُه أو فشله في إنشاء الإعلان المحلي.

هذا قرار نطاق وتشغيل، لا حكم بأن هذه النماذج غير مفيدة علمياً. فالنماذج المفتوحة قد تكون مناسبة لتجارب يدوية أو لبنية تملك GPU، لكنها ليست حلاً مجانياً مستقراً وذا خصوصية قابلة للضمان داخل استضافة هذا المشروع.

## معيار القبول

| المعيار الإلزامي | المقصود في المشروع |
|---|---|
| بلا بطاقة ولا دفع | لا اشتراك ولا رصيد مدفوع ولا إعداد فواتير، وليس مجرد عرض تجريبي قصير غير موثق. |
| Try‑On فعلي | صورة شخص أو نموذج + صورة قطعة → نتيجة تلبيس، وليس تصنيفاً أو كتالوجاً أو توصية. |
| تكامل خادمي موثق | API أو endpoint مستقر موثق يسمح بإبقاء المفتاح في الخادم، ويقبل الإلغاء والمهلة والنتيجة الآمنة. |
| خصوصية قابلة للضبط | سياسة احتفاظ معلنة للمدخلات والمخرجات، مع عدم وضع الصور أو روابطها في سجلات التطبيق أو التخزين الدائم بلا موافقة. |
| ملاءمة تشغيلية | لا حصة يومية صغيرة أو طابور موارد مشتركة أو حالة Demo فقط تجعل النتيجة غير مضمونة للتاجر. |

## نتائج المصادر التي قدمها المالك

| المصدر | ما الذي تحقّق فعلياً | القرار |
|---|---|---|
| [Apipheny Free APIs][1] | صفحة دليل عام لواجهات عامة للاختبار بلا مفتاح؛ لا تعرض Virtual Try‑On أو مولد أزياء. | **مرفوض:** ليس مزود Try‑On. |
| [The New Black][2] | منصة أزياء تجارية تعرض Try‑On داخل منتجها، لكنها لا توثق في الصفحة API عامة مجانية بلا بطاقة؛ الواجهة تشير إلى التسجيل والدخول ومنتج للعلامات التجارية. | **مرفوض حالياً:** لا عقد API مجاني موثق. |
| [Choyce][3] | يحلل إيصالات البريد لإنشاء ملف تفضيلات ويدفع التوصيات إلى Klaviyo؛ لا يولد صوراً ولا يلبس قطعاً. | **مرفوض:** خارج النطاق. |
| [PoweredByAI / API4AI Fashion][4] | الدليل يصف تعرّف الملابس والإكسسوارات وصناديق الإحاطة واحتمالات الثقة؛ وهو تحليل صور لا Try‑On. | **مرفوض:** ليس توليداً. |
| [ModelsLab Fashion 1.0][5] | Try‑On حقيقي، لكن السعر المعلن `$0.0047` لكل طلب، مع ظهور خطة مفتوحة بـ`$149/month` وتسجيل دخول للتوليد. | **مرفوض:** مدفوع. |
| [RapidAPI Fashion][6] | مجموعة كتالوجات وبحث منتجات وفعاليات؛ أمثلة المجاني تتعلق ببيانات المنتجات أو المكياج، وليست Try‑On. | **مرفوض:** ليست خدمة تلبيس. |
| [`madiha2323/Api`][7] | مستودع صفحات HTML و`data.json` لعرض كتالوج قمصان وأحذية وجاكيتات؛ لا نموذج توليدي ولا خادم Try‑On. | **مرفوض:** ليس حل ذكاء اصطناعي للتلبيس. |

## نتائج البدائل الإضافية

| المصدر | النتيجة الموثقة | أثرها على قرار المشروع |
|---|---|---|
| [FASHN VTON v1.5 Space][8] و[IDM‑VTON Space][9] | المساحتان ظاهرتان بحالة **Running on Zero**. توضح Hugging Face أن ZeroGPU بنية مشتركة للمساحات والعروض، وأن الحساب المجاني يملك **5 دقائق GPU يومياً** فقط، مع أولوية متوسطة وطوابير محتملة؛ كما تذكر أن التوافق قد يكون محدوداً مقارنة بالـGPU التقليدي. [10] | **غير مناسب كخلفية تلقائية للتطبيق.** يصلح لتجربة يدوية تعليمية موقتة من واجهة Space، لا كمزود ثابت لصور متجر. |
| [fal.ai Virtual Try‑On][11] | السعر المنشور لمسار Virtual Try‑On هو `$0.04` لكل صورة. | **مرفوض:** مدفوع؛ لا توجد في المصادر الرسمية المفحوصة حصة Try‑On دائمة بلا بطاقة تثبت خلاف ذلك. |
| [Replicate IDM‑VTON][12] | التكلفة التقريبية المعلنة `$0.024` لكل تشغيل على A100، والرخصة المذكورة للنموذج تسمح بالاستخدام غير التجاري فقط. كما تؤكد وثائق Replicate أن النماذج المجانية المحددة فقط تعمل بلا تكلفة «لفترة»، ثم يُطلب إعداد الفوترة. [13] | **مرفوض:** مدفوع عملياً ولا يحقق شرط عدم الفوترة؛ الملاءمة غير التجارية وحدها لا تكفي. |

## الخصوصية وعدم إرسال الصور

لم تُرسل أي صورة أو بيانات تاجر أثناء البحث. وهذا مهم لأن توفر endpoint تقني لا يعني تلقائياً أن سياسة البيانات مناسبة للتطبيق. فعلى سبيل المثال، تذكر Replicate أن بيانات استدعاءات API تُحذف افتراضياً بعد ساعة، بينما تبقى نتائج واجهة الويب حتى يحذفها المستخدم. [14] وتذكر fal أن مدخلات ومخرجات الوسائط قد تُخزن على CDN، وأن JSON الخاص بالطلب يحتفظ به افتراضياً 30 يوماً ما لم تُستخدم رؤوس تحكم مخصصة. [15]

> لذلك لا يجوز ربط أي Space عام أو صفحة Demo مباشرة بالتطبيق بغرض تجاوز متطلبات المزود. المسار الصحيح يتطلب موافقة عربية صريحة قبل الشبكة، مزوداً موثقاً، مفتاحاً محفوظاً في الخادم فقط، مهلة وإلغاء، وحذفاً/انتهاءً موثقاً للوسائط.

## ما يبقى متاحاً الآن

| المسار | ما يمكن فعله | ما لا يتم |
|---|---|---|
| **المسار المحلي — الموصى به** | رفع القطعة، تحسينها محلياً، إزالة الخلفية المحلية، ووضعها داخل Canvas لتوليد الإعلان من دون إرسالها إلى مزود Try‑On. | لا ينتج شخصاً مرتدياً القطعة. |
| **تجربة تعليمية يدوية منفصلة** | يمكن للمالك، إن رغب لاحقاً، تجربة FASHN أو IDM‑VTON من واجهة Hugging Face مباشرة، مع حساب مجاني وحذر كامل من رفع صور خاصة أو حساسة. | لا تُوصل بالتطبيق، ولا تضمن نتيجة أو سرعة أو توفر يومي، ولا تحفظ داخل المشروع. |
| **تكامل مستقبلي اختياري** | يعاد فتحه فقط بعد اختيار مزود يمر بمعيار القبول كاملاً ووضع مفتاحه في متغير خادمي بطريقة آمنة. | لا يُشترى رصيد ولا تُضاف بطاقة ولا يُرسل مفتاح أو صورة في العميل. |

## شروط إعادة التقييم

يعاد تقييم أي مزود جديد فقط إذا قدّم وثائق رسمية تثبت أن الحصة المجانية بلا بطاقة **مخصصة لـAPI الفعلي** وليست صفحة Demo، وتحدد بوضوح حد الطلبات، وسياسة الاحتفاظ بالصور، وآلية حذفها، والرخصة، وحدود الاستقرار. عندها تجرى تجربة هندسية مستقلة ببيانات اختبار غير حقيقية، ثم تضاف اختبارات النجاح والرفض والمهلة والإلغاء والنتيجة المتأخرة والرجوع المحلي قبل أي تشغيل للمستخدمين.
