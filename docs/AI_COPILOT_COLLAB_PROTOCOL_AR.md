# بروتوكول التعاون مع GitHub Copilot

## المبدأ

يعمل Copilot **كمراجع ومساهم خارجي**، وليس كمالك للمستودع. لا يحصل على صلاحية كتابة أو دمج أو أسرار أو قاعدة بيانات أو جلسة Render. يوفر المستودع العام القراءة المطلوبة، ويبقى الدمج النهائي بعد مراجعة Patch واختباراته في المشروع.

رابط محادثة Copilot خاص بحساب GitHub الذي أنشأه؛ لذلك لا يمثل قناة وصول للنماذج الأخرى ولا يحتاج إلى مشاركته مع أي متسابق. يجب استخدامه من جلسة GitHub الخاصة بالمالك على الهاتف.

## دورة العمل الصارمة

| المرحلة | ما يرسله Copilot | ما لا يفعله |
|---|---|---|
| 0. قراءة | SHA الأساس، والملفات المقروءة، وثلاثة قيود من `AI_CONTEXT.md` | لا يكتب كوداً ولا يقترح إعادة بناء |
| 1. Discovery | فرضية واحدة، ملف/مسار محدد، وخطة اختبار محلي | لا يعد بتطوير شامل ولا يختار مكتبات جديدة |
| 2. اعتماد النطاق | `IMPLEMENTATION_MAP.md` قصير يبين الملفات المتغيرة وغير المتغيرة | لا ينشئ فرعاً ولا يحصل على صلاحية كتابة |
| 3. التنفيذ | `PATCH.diff` + اختبارات + نتائج حقيقية | لا يرفع مشروعاً كاملاً أو أسراراً أو بيانات |
| 4. المراجعة | يرسل المالك التسليم إلى مدير المشروع للفحص | لا يدمج Copilot أي شيء بنفسه |

## قاعدة المهمة الواحدة

لا تطلب من Copilot «حسّن المشروع» أو «أعد تصميمه». كل جولة تختار هدفاً واحداً قابلاً للقياس، مثل: إثبات حد جسم طلب غير مناسب وإصلاحه محلياً مع اختبار سلبي. لا تبدأ مهمة ثانية قبل قرار قبول/رفض الأولى.

## حماية الفكرة الأساسية

يرفض أي تسليم يضيف Renderer أو Canvas ثانياً، أو يعيد بناء Store/Cache أو Theme Registry قائم بلا دليل، أو يحول المعالجة المحلية المتسلسلة إلى توازٍ غير مقاس، أو ينقل قاعدة البيانات، أو يضيف API/secret، أو يغير إعداد Render. كل تغيير يجب أن يذكر سبباً مثبتاً وSHA وقابلية تراجع واختبار Regression.

## التسليم المقبول

لا تقبل نصاً في المحادثة وحده. التسليم الذي يستحق المراجعة يحتوي: `PATCH.diff`، و`changed-files/`، و`CHALLENGE_REPORT.md`، و`TEST_EVIDENCE.md`، و`SECURITY_SCOPE.md`. يطبق مدير المشروع الـPatch على SHA المحدد ثم يعيد تشغيل الاختبارات قبل الدمج أو الرفض.
